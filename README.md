# 픽셀 쇼

최상단에서 **선거 · 경마 · 난투**를 고르는 정적 랜덤 추첨 웹 앱입니다. 게임을 바꿔도 이름 2~10개의 명단이 유지됩니다. 선거는 준비된 다섯 테마만 선택하며 자유 주제 입력은 제공하지 않습니다.

- **경마**: 야간 경기장의 출발 게이트, 가까운 경합을 따라가는 중계, 12종 이야기 중 세 사건, 마지막 직선과 사진 판정으로 진행됩니다. 진로 막힘·안쪽 돌파·바깥 추격 등의 중계는 실제 차선과 순위 변화에 연결됩니다.
- **장외 난투**: 전원이 모래판에 고르게 흩어져 시작합니다. 협공·미끼·역습·배신·버티기·들배지기를 사용하고, 잡고 피하는 비탈락 교환도 계속됩니다. 사건의 접근·접촉·전환 단계와 당사자 번호를 함께 표시하며, 협공은 두 선수가 함께 잡고 들고, 배신은 임시 동맹이 손을 놓는 행동으로 보여줍니다. 선수마다 피부 팔레트를 통일하고, 이동·잡기·들기·투척·착지·회복을 연결합니다. 여섯 층 관중석과 개별 응원, 조명·모래 흔적을 그리며, 착지 뒤 장외 순위를 확정합니다.
- **선거**: 각 득표율 바로 아래 받은 표수를 표시합니다. 마지막 구간은 모든 생존 후보의 질주와 결승선 통과, 제동·호흡으로 연결하고, 당선 순간 확정 도장과 점프, 후보별 반응을 보여줍니다.

경마와 난투의 전체 순위는 Web Crypto의 rejection sampling과 Fisher–Yates 섞기로 먼저 정합니다. 모든 참가자는 입력 위치와 관계없이 각 순위에 같은 확률을 가지며, 경기 연출은 그 순위를 보존합니다. 두 게임에는 찜이나 응원 선택이 없습니다. 일시정지, 결과 바로 보기, 같은 명단으로 다시 뽑기를 제공합니다.

난투는 판마다 진행 길이를 별도로 선택합니다. 선거와 경마는 기존 개표·한 바퀴 경주의 진행 길이를 유지합니다. 세 모드 모두 남은 결과 시간을 표시하지 않으며, 일시정지·계속 보기·결과 바로 보기는 해당 판의 진행 시간을 기준으로 동작합니다. 난투의 진행 길이는 순위 추첨과 독립입니다.

후보 2~10명 중 한 명을 동일 확률로 뽑고, 픽셀 선거 쇼로 발표하는 정적 웹 앱입니다. 신문 호외와 시민들의 투표에 이어 실시간 개표, 몸싸움과 돌발 사건, 막판 접전, 당선 세리머니가 진행됩니다. 60가지 사건 중 매번 다른 조합이 등장하며, 간식 뇌물이나 커피 쿠폰 사건에 연루된 후보는 탈락할 수 있습니다. 사건마다 당사자 등장, 행동과 대사, 판정, 순위 반영을 보여줍니다. 판정 전까지 개표를 멈추고, 판정 후 실제 전후 순위를 표시합니다. 지나간 사건은 기록을 눌러 다시 읽을 수 있으며, 기록을 여는 동안 재생이 멈춥니다. 응원 선택은 당선 확률에 영향을 주지 않습니다. 이름과 주제는 같은 브라우저 탭의 세션에 저장됩니다. 표시되는 사건·투표수·득표율은 게임 연출 데이터입니다.

당선자는 시작할 때 Web Crypto의 rejection sampling으로 먼저 정합니다. 사건과 탈락 연출은 그 결과를 보존하면서 생성하므로, 입력 순서와 관계없이 모든 후보의 당선 확률은 `1 / 후보 수`입니다. 한 판에는 최대 세 사건이 등장하며 최소 두 후보가 마지막까지 경합합니다.

## 로컬 실행

```bash
npm ci
npm run dev
```

## 검증 및 배포 준비

```bash
npm test
npm run build
npm run preview
```

Vercel에서는 이 저장소를 연결하고 Framework Preset을 **Vite**, Build Command를 `npm run build`, Output Directory를 `dist`로 설정하면 됩니다. 서버, 환경 변수, 데이터베이스는 필요하지 않습니다. 배포는 아직 실행하지 않았습니다.

## 구조

- `src/election.ts`: Web Crypto 기반 균등 추첨, 투표수 및 개표 연출 데이터
- `src/GameStage.tsx`: Phaser 픽셀 무대와 장면
- `src/game/`: 연속 장면 전환, 팔·다리 관절 캐릭터, 투표와 개표 무대
- `src/show.ts`: 58초 진행 시간, 사건 단계와 판정, 속보 문구
- `src/storyCatalog.ts`: 6종류, 60개의 돌발 사건
- `src/BroadcastShow.tsx`: 방송 자막, 순위표, 사건 카드와 다시 보기
- `src/App.tsx`: 입력, 진행, 개표 및 결과 UI
- `src/sports.ts`: 경마·난투의 균등 전체 순위 추첨
- `src/playbackTiming.ts`: 난투의 판별 진행 길이, 선거·경마 기본 길이
- `src/RacingShow.tsx`: 경마장, 말과 기수, 실시간 순위와 결승 판정
- `src/racingNarrative.ts`: 사건과 실제 순위 변화를 연결하는 전진 거리 타임라인
- `src/ArenaShow.tsx`: 전원 동시 모래판 난투, 장외 탈락과 확정 순위
- `src/arenaLogic.ts`: 생존자 전술, 비탈락 교환, 투척 궤적과 착지 후 순위
- `src/ArenaStory.tsx`, `src/arenaStoryLogic.ts`: 동작과 같은 사건 단계, 협공·동맹·배신 관계 표시
- `src/game/ArenaFighter.ts`: 이동 거리에 따른 발걸음과 관절 캐릭터
- `src/game/arenaArt.ts`: 경기장 구조, 모래판, 관중과 응원 동작

개발 서버에서 `tests/stage-preview.html`과 `tests/sports-preview.html`을 열면 특정 시간대, 2~10명, 긴 이름으로 장면을 검증할 수 있습니다. 검증 화면은 프로덕션 번들에 포함하지 않습니다.

사건 기록은 해당 추첨 화면에만 유지됩니다. 사운드, 로그인, 기록의 영구 저장, 실제 투표 및 공유 기능은 MVP 범위 밖입니다.
