# 픽셀 랜뽑

최상단에서 **난투 · 경마 · 투표 · 사다리**를 고르는 정적 랜덤 추첨 웹 앱입니다. 게임을 바꿔도 이름 2~10개의 명단이 유지됩니다. 투표는 준비된 다섯 테마 중 하나를 고르고, 사다리는 참가자 수만큼 있는 도착 문 중 당첨 지점 하나를 먼저 고릅니다. 이름과 테마, 선택한 지점은 같은 브라우저 탭의 세션에 저장됩니다.

- **장외 난투**: 전원이 모래판에 고르게 흩어져 시작합니다. 협공·미끼·역습·배신·버티기·들배지기를 사용하고, 잡고 피하는 비탈락 교환도 계속됩니다. 사건의 접근·접촉·전환 단계와 당사자 번호를 함께 표시하며, 협공은 두 선수가 함께 잡고 들고, 배신은 임시 동맹이 손을 놓는 행동으로 보여줍니다. 선수마다 피부 팔레트를 통일하고, 이동·잡기·들기·투척·착지·회복을 연결합니다. 여섯 층 관중석과 개별 응원, 조명·모래 흔적을 그리며, 착지 뒤 장외 순위를 확정합니다.
- **경마**: 관중석·조명·레일이 있는 야간 타원 코스를 전체 탑뷰로 보여주고, 2~10마리의 스타팅게이트를 공동 출발선에 나란히 정렬합니다. 말들은 동시에 출발하며, 연속된 실제 주행 거리에 따라 카메라가 이동합니다. 선두 세 마리와 사건에서 실제로 추월하는 상대를 따라가고, 12종 이야기 중 세 사건을 진로 막힘·안쪽 돌파·바깥 추격 등의 차선과 순위 변화로 보여줍니다. 마지막 직선에서는 실제 코끝의 결승선 통과 순서대로 완주하며 사진 판정으로 이어집니다. 말의 발 접지와 기수의 안장 접촉을 유지하고, 우승한 말과 기수는 걷기 → 정지 → 한손 인사로 마무리합니다.
- **투표**: 신문 호외와 시민들의 투표에 이어 실시간 개표, 돌발 사건, 막판 접전, 당선 세리머니가 진행됩니다. 각 득표율 바로 아래 받은 표수를 표시합니다. 마지막 구간은 모든 생존 후보의 질주와 결승선 통과, 제동·호흡으로 연결하고, 당선 순간 확정 도장과 점프, 후보별 반응을 보여줍니다.
- **사다리 오르기**: 참가자마다 세로 사다리 하나에서 출발하고, 함정을 거칠 때 실제로 다른 사다리로 넘어갑니다. 모든 참가자가 최소 두 번 줄을 바꾸며, 매 판 줄 스윙·공중 점프·옆줄 추락과 붙잡기를 보여줍니다. 줄에 매달려 크게 건너거나 발을 떼고 뛰어오르고, 손을 놓친 사람은 옆줄의 손잡이를 잡아 몸을 끌어올립니다. 교차하는 두 사람도 각자 다른 공중 궤적으로 이동합니다. 자기 옆길을 건넌 사람은 바로 계속 올라가며, 다른 참가자의 사건이 끝날 때까지 함께 멈추지 않습니다. 16가지 사건 중 매 판 3~4가지를 집중 중계합니다. 먼저 고른 당첨 문에 실제로 들어간 한 사람을 발표하며, 도착 속도로 순위를 정하지 않습니다.

난투의 이름표는 선수 발밑에 고정하며, 모든 사람보다 뒤 레이어에 그려 선수의 몸을 가리지 않습니다. 경기 중에는 현재 위치에서 다음 상대를 찾아 움직이고, 결과에서는 실제 1·2·3위가 금·은·동 시상대로 걸어옵니다. 바지는 골반과 허벅지에 이어지며, 박수는 두 손바닥을 모아 잠깐 맞닿은 뒤 펼치는 동작으로 그립니다.

경마의 모든 말은 중계 화면에서 같은 크기로 그립니다. 순위가 바뀌어도 말의 세로 주행 위치를 유지하고, 선두권 추월에 나서는 상대는 미리 카메라로 추적합니다. 탑뷰에는 입체 관중석·정원·분수·전광판·이중 레일을 배치하고, 관절 움직임과 발굽 먼지로 질주를 표현합니다. 막판에는 전체 말의 간격을 한꺼번에 압축하지 않고 개별 추월을 이어갑니다. 사이트 아이콘과 상단 로고는 픽셀 주사위와 뽑기 상자를 사용합니다.

경마와 난투의 전체 순위는 Web Crypto의 rejection sampling과 Fisher–Yates 섞기로 먼저 정합니다. 모든 참가자는 입력 위치와 관계없이 각 순위에 같은 확률을 가지며, 경기 연출은 그 순위를 보존합니다. 일시정지, 결과 바로 보기, 같은 명단으로 다시 뽑기를 제공합니다.

난투는 판마다 진행 길이를 별도로 선택합니다. 투표는 58초, 경마와 사다리는 44초로 진행합니다. 모든 모드에서 남은 결과 시간을 표시하지 않으며, 일시정지·계속 보기·결과 바로 보기는 해당 판의 진행 시간을 기준으로 동작합니다. 난투의 진행 길이는 순위 추첨과 독립입니다.

사다리의 도착 문 배정도 동일한 균등 섞기를 사용합니다. 가로다리는 그 배정으로 이어지는 실제 경로로 만들고, 함정에서 회복한 뒤에도 경로를 이어갑니다. 선택한 문에 도착할 확률은 모든 참가자에게 `1 / 참가자 수`로 같습니다. 당첨 지점은 시작한 뒤 바꿀 수 없습니다.

투표에서는 60가지 사건 중 매번 다른 조합이 등장하며, 간식 뇌물이나 커피 쿠폰 사건에 연루된 후보는 탈락할 수 있습니다. 사건마다 당사자 등장, 행동과 대사, 판정, 순위 반영을 보여줍니다. 판정 전까지 개표를 멈추고, 판정 후 실제 전후 순위를 표시합니다. 지나간 사건은 기록을 눌러 다시 읽을 수 있으며, 기록을 여는 동안 재생이 멈춥니다. 표시되는 사건·투표수·득표율은 게임 연출 데이터입니다.

당선자는 시작할 때 Web Crypto의 rejection sampling으로 먼저 정합니다. 사건과 탈락 연출은 그 결과를 보존하면서 생성하므로, 입력 순서와 관계없이 모든 후보의 당선 확률은 `1 / 후보 수`입니다. 한 판에는 최대 세 사건이 등장하며 최소 두 후보가 마지막까지 경합합니다.

## 로컬 실행

```bash
npm ci
npm run dev
```

## 검증 및 배포 준비

```bash
npm test
npm run build
npm run preview
```

Vercel에서는 이 저장소를 연결하고 Framework Preset을 **Vite**, Build Command를 `npm run build`, Output Directory를 `dist`로 설정하면 됩니다. 서버, 환경 변수, 데이터베이스는 필요하지 않습니다. 배포는 아직 실행하지 않았습니다.

## 구조

- `src/election.ts`: Web Crypto 기반 균등 추첨, 투표수 및 개표 연출 데이터
- `src/GameStage.tsx`: Phaser 픽셀 무대와 장면
- `src/game/`: 연속 장면 전환, 팔·다리 관절 캐릭터, 투표와 개표 무대
- `src/show.ts`: 58초 진행 시간, 사건 단계와 판정, 속보 문구
- `src/storyCatalog.ts`: 6종류, 60개의 돌발 사건
- `src/BroadcastShow.tsx`: 방송 자막, 순위표, 사건 카드와 다시 보기
- `src/App.tsx`: 게임 선택, 이름·테마 입력, 재생 및 결과 UI
- `src/sports.ts`: 경마·난투의 균등 전체 순위 추첨
- `src/playbackTiming.ts`: 난투의 판별 진행 길이, 투표·경마·사다리 기본 길이
- `src/RacingShow.tsx`: 경마장, 말과 기수, 실시간 순위와 결승 판정
- `src/racingCourse.ts`: 전체 코스 탑뷰, 공동 출발선과 스타팅게이트, 실제 거리의 말 위치
- `src/racingArt.ts`: 말·기수 관절, 발 접지, 중계 경기장과 우승 인사 작화
- `src/racingNarrative.ts`: 사건과 실제 순위 변화를 연결하는 전진 거리 타임라인
- `src/ArenaShow.tsx`: 전원 동시 모래판 난투, 장외 탈락과 확정 순위
- `src/arenaLogic.ts`: 생존자 전술, 비탈락 교환, 투척 궤적과 착지 후 순위
- `src/ArenaStory.tsx`, `src/arenaStoryLogic.ts`: 동작과 같은 사건 단계, 협공·동맹·배신 관계 표시
- `src/game/ArenaFighter.ts`: 이동 거리에 따른 발걸음과 관절 캐릭터
- `src/game/arenaArt.ts`: 경기장 구조, 모래판, 관중과 응원 동작
- `src/LadderShow.tsx`: 선택한 당첨 문, 사다리 무대와 참가자 상태
- `src/ladderLogic.ts`: 층별 옆길 경로, 함정 사건, 실제 도착 문 배정
- `src/game/ladderArt.ts`: 픽셀 타워와 손·발 접지, 매달리기와 추락 작화

개발 서버에서 `tests/stage-preview.html`, `tests/sports-preview.html`, `tests/ladder-preview.html`을 열면 특정 시간대, 2~10명, 긴 이름과 당첨 지점으로 장면을 검증할 수 있습니다. 검증 화면은 프로덕션 번들에 포함하지 않습니다.

사건 기록은 해당 추첨 화면에만 유지됩니다. 사운드, 로그인, 기록의 영구 저장, 실제 투표 및 공유 기능은 MVP 범위 밖입니다.
